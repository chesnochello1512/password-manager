# Password Manager

Полностью локальный менеджер паролей для Windows 10/11. Приложение хранит логины, пароли, ссылки, категории и заметки в зашифрованном виде и не использует интернет, облака, аккаунты или серверную часть.

![Password Manager](assets/icon.png)

## Возможности

- Три области: боковая панель категорий, список записей и подробная карточка.
- Добавление, редактирование и удаление записей с подтверждением.
- Скрытие/показ пароля с автоматическим возвратом к маске.
- Копирование логина, пароля и ссылки.
- Автоочистка буфера обмена (15/30/60 секунд или отключена). Буфер очищается только если там всё ещё находится скопированный пароль.
- Поиск по названию, логину и сайту, фильтрация по категориям и избранному.
- Редактируемые категории: добавление, переименование, удаление с переносом записей в «Другое».
- Генератор паролей: длина 8–64, наборы символов, криптостойкий `secrets`. Для сгенерированных паролей показывается оценка в битах, для введённых вручную — эвристика с предупреждениями о повторах, последовательностях и популярных паролях.
- Автоблокировка: никогда / 1 / 5 / 10 / 15 минут, сброс по активности, ручная блокировка `Ctrl+L`.
- Зашифрованные резервные копии, проверка целостности и восстановление.
- Смена мастер-пароля с полной перешифровкой хранилища.
- Тёмная тема, кастомный заголовок окна, SVG-иконки и аккуратные анимации.
- Горячие клавиши: `Ctrl+N` — новая запись, `Ctrl+F` — поиск, `Ctrl+L` — блокировка.

## Безопасность

- **Argon2id** (`argon2-cffi`): 64 МиБ памяти, 3 итерации, 4 потока, соль 16 байт. Параметры и соль хранятся в метаданных хранилища, ключ — только в оперативной памяти.
- **AES-256-GCM** (`cryptography`) для каждой записи. Уникальный 96-битный nonce генерируется через `os.urandom` при каждом шифровании; тег GCM проверяет целостность.
- В открытом виде в SQLite находятся только `id`, временные метки, версии формата и шифротекст. Названия сервисов, логины, пароли, URL, заметки, избранное и категории зашифрованы.
- AAD привязывает шифротекст к идентификатору записи и версии формата: подмена или перенос блока между записями обнаруживается.
- Мастер-пароль не сохраняется. Проверка выполняется через зашифрованный верификатор.
- Поиск и фильтрация работают в памяти после разблокировки; индексы с открытым текстом не создаются.
- При блокировке ключ затирается в `bytearray`, расшифрованные записи удаляются из памяти, буфер обмена очищается, если содержит наш секрет.
- Смена мастер-пароля: новая соль → новый ключ → перешифровка всех записей и настроек → атомарная замена файла. Во время перешифровки блокировка и закрытие приложения откладываются до безопасного завершения операции. При сбое до замены файла старое хранилище остаётся целым; если сбой произошёл после замены, приложение честно сообщает, что действует новый пароль, и требует войти им.
- Резервная копия — снимок уже зашифрованного SQLite-файла (`.pmvault`). Для копирования пароль не нужен; проверка структуры и `PRAGMA integrity_check` выполняются без расшифровки.
- Приложение не содержит сетевого кода и не отправляет данные наружу.

### Ограничения очистки памяти и буфера

- Затирание ключа в `bytearray` — это **best-effort** защита. Python и Qt создают неизменяемые копии строк и внутренние буферы виджетов, которые невозможно гарантированно стереть из интерпретатора.
- Секреты минимизируются по времени жизни: поля диалогов очищаются при закрытии и блокировке, расшифрованные записи удаляются из памяти при lock. Но полная гарантия очистки всех копий в оперативной памяти недостижима в Python/Qt.
- Системный буфер обмена находится вне контроля приложения: история буфера, облачная синхронизация и сторонние перехватчики могут сохранить скопированный пароль даже после автоочистки.
- Замена файла хранилища на более старую корректную копию (rollback) не обнаруживается шифрованием: AES-GCM подтверждает целостность блоков, но не «свежесть» всей базы.
- Открытые служебные поля `created_at`, `updated_at` и `key_version` не входят в AAD формата v1: изменение этих столбцов в SQLite не вызовет ошибку GCM. Содержимое записей при этом остаётся защищённым.

### Важно

- **Забытый мастер-пароль восстановить невозможно.** Нет «секретного вопроса» или обхода. Сохраните пароль в надёжном месте.
- Резервная копия защищена тем мастер-паролем, который действовал на момент её создания. После восстановления вводится пароль из копии.
- Менеджер паролей не защищает от вредоносного ПО, кейлоггеров и захвата экрана. Используйте доверенную систему и не запускайте неизвестные программы.
- EXE пока не подписан сертификатом. Windows SmartScreen может показать предупреждение. Сверяйте SHA-256 с файлом `SHA256SUMS.txt` из релиза или собирайте приложение из исходников; не запускайте файлы из непроверенных источников.

## Требования

- Windows 10/11 (64-bit).
- Python 3.10.8 для запуска из исходников и сборки. Допускаются 3.10–3.13, но целевая версия — **3.10.8**.
- Зависимости: PySide6 6.8.3, argon2-cffi 23.1.0, cryptography 50.0.2.
- Для тестов и сборки: pytest 8.3.5, PyInstaller 6.22.3, ruff 0.9.10, mypy 1.15.0, pip-audit 2.10.1.

## Запуск из исходников

```bat
cd password_manager
py -3.10 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python main.py
```

При первом запуске приложение предложит создать мастер-пароль (минимум 8 символов). При следующих запусках — ввести его.

### Расположение данных

По умолчанию:

```
%APPDATA%\PasswordManager\vault.db
%APPDATA%\PasswordManager\logs\app.log
```

Можно задать другой каталог переменной окружения `PM_DATA_DIR` (например, для портативного режима):

```bat
set PM_DATA_DIR=%CD%\data
python main.py
```

Каталог `data/` в проекте предназначен для такого режима и не содержит секретов в репозитории.

## Сборка EXE

Дважды щёлкните `build.bat` или выполните в командной строке:

```bat
build.bat
```

Скрипт:

1. Находит Python 3.10+.
2. Создаёт `.venv` и устанавливает зависимости.
3. Запускает автоматические тесты.
4. Собирает одиночный файл через PyInstaller.
5. Кладёт результат в `dist\PasswordManager.exe`.

Готовый файл:

```
dist\PasswordManager.exe
```

Python на целевой машине не требуется — PyInstaller включает интерпретатор и библиотеки. Размер файла — ориентировочно 90–130 МБ, первый запуск может занять несколько секунд.

Для сборки рекомендуется скопировать проект с общей папки на локальный диск Windows: PyInstaller создаёт тысячи временных файлов, и работа через VirtualBox Shared Folder может быть заметно медленнее.

Если нужно собрать без тестов (например, на машине без графической сессии):

```bat
set SKIP_TESTS=1
build.bat
```

## Тесты

```bat
.venv\Scripts\activate
set QT_QPA_PLATFORM=offscreen
python -m pytest -q
```

Покрываются:

- Argon2id и AES-256-GCM: round-trip, уникальные nonce, неверный ключ, подмена шифротекста/AAD, верификатор.
- Неверный мастер-пароль и повреждённое хранилище.
- Генератор: границы длины, наборы символов, энтропия.
- CRUD, поиск, фильтры, избранное, категории, перезагрузка хранилища.
- Отсутствие открытых секретов в файле БД.
- Резервные копии: создание, проверка, повреждение, восстановление и страховочная копия.
- Смена мастер-пароля с перешифровкой, включая отложенную блокировку и сбой после замены файла.
- Атомарность удаления категории и сохранения настроек при инъекции ошибок.
- Оценка стойкости: повторы, последовательности, популярные пароли и сгенерированные значения.
- UI-smoke: главное окно, карточки, скрытие пароля, буфер, генератор, настройки, вход/разблокировка.

Статические проверки и CI:

```bat
.venv\Scripts\activate
ruff check app tests tools main.py
mypy
pip-audit -r requirements.txt
```

GitHub Actions запускает тесты на Windows и Linux (offscreen), `ruff`, `mypy` для ядра и `pip-audit`. Workflow релиза собирает EXE и публикует `SHA256SUMS.txt`. Замеры на синтетических данных: `python tools/bench_vault.py --records 1000`.

## Резервное копирование

- **Создать копию:** Настройки → Резервные копии → «Создать копию». Файл `.pmvault` уже зашифрован.
- **Проверить:** «Проверить копию» — проверяет SQLite, метаданные, версию формата и размеры nonce/шифротекста без пароля.
- **Восстановить:** «Восстановить» → выбрать файл → подтвердить. Перед заменой создаётся `vault.db.bak-<дата>` в каталоге данных. После восстановления нужно ввести мастер-пароль из копии.

## Диагностика

- Журнал: `%APPDATA%\PasswordManager\logs\app.log`. Секреты и пароли в журнал не пишутся.
- Если хранилище повреждено, приложение сообщит об этом при запуске. Замените `vault.db` резервной копией вручную или через страницу настроек после восстановления рабочего хранилища.
- Удаление `vault.db` означает потерю всех записей, если нет резервной копии.
- Не запускайте два экземпляра приложения: используется блокировка `app.lock`.
